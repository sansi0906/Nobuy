> 覆盖标记说明
> - **UI 自动**：`node tools/e2e.js`，用 miniprogram-automator 真实点界面，断言渲染结果（当前 **60 项全过**）
> - **单测**：`node tools/test_storage.js`，内存模拟 `wx` 存储跑数据层（当前 **69 项全过**）
> - **仅弹窗**：按钮点得到、确认框能弹，但原生弹窗的「确定」按钮自动化点不到 → 只断言弹窗出现，确认后的写入由单测覆盖
> - **手动**：需要真人点击或肉眼判断，未纳入自动化

## 三、未覆盖 / 只能手动（14 项）

| 编号 | 用例 | 为什么没自动 | 怎么验 |
|---|---|---|---|
| M01 | 弹窗「确定」后的界面效果（恢复后详情立刻变冷静中、删除后列表刷新） | `wx.showModal` 是原生弹窗，automator 点不到确定；写死在 mock 里也没什么可信度 | 数据层已由 D48–D54 覆盖，界面效果手动点一次 |
| M02 | 我页清空数据的**二次确认** | 第一次弹窗都点不到，更过不了第二层 | 手动点两次 |
| M03 | 分类「管理」：选分类 → 改名 / 删除 | `wx.showActionSheet` 同上 | 手动，或后续补 callMethod 直调 |
| M04 | 新建自定义分类（含重名、超 6 字、满 20 个） | 依赖 `showModal` editable 输入 | 手动（数据层 D24–D26 已覆盖） |
| M05 | 长按分类改名 / 删除 | 长按 + actionSheet 双重点不到 | 手动 |
| M06 | 详情编辑：切换分类、改价格、改备注 | 本次只测了改名和数量，选择器都可用但断言成本高 | 可补自动化（下一轮） |
| M07 | 新增页「取消」放弃确认 | 原生导航返回键点不到，只能调 `onCancel` | 手动 |
| M08 | 决策页「再想想」返回详情 | 纯 navigateBack，价值低 | 手动 |
| M09 | 头像选择（chooseAvatar） | 需要真实相册/系统裁剪 UI | 手动，必须真机 |
| M10 | tabBar 角标（过期数） | 原生 tabBar，DOM 里查不到 | 截图比对 |
| M11 | 视觉层：配色、金币/灰印、tab 图标、字号分档、红字醒目 | 像素级差异，需要基准截图 + 比对 | 人工看 或 后续接截图 diff |
| M12 | 30 秒轮询到期自动刷新 | 需要真等 30 秒，会拖慢回归 | 单独慢跑脚本 |
| M13 | 脏数据价格在界面的显示（「—」） | 数据层已覆盖（D11），界面未加用例 | 可补自动化 |
| M14 | 真机差异（iOS/Android 基础库、存储配额、客服按钮） | 模拟器≠真机 | 体验版手测 |

## 四、结论

- 逻辑与数据口径：**全覆盖**（69 项断言，含金额、统计、连续天数、分类、回收站、清空、成就阈值、写入失败兜底）。
- 界面主流程：**65 项覆盖**，10 个页面全部进入自动化，含主流程、空态、引导、校验拦截。
- 缺口集中在两类：**原生弹窗/操作面板的“确认”分支**（机制所限，靠数据层兜底）、**视觉与真机表现**（需要截图比对或真机）。

跑法：

```powershell
node tools\test_storage.js   # 69 项
node tools\e2e.js            # 60 项（需开发者工具开着、服务端口开着）
```
